# 文档维护

适用版本：Aster 1.2.0-beta.7。

## 面向读者组织内容

- README 介绍产品、平台下载方式和文档入口；快速开始提供一条可复现的使用流程。
- 使用手册说明当前行为、操作步骤及必要限制；FAQ 按用户看到的症状组织。
- 方法文档说明定义、参数、输出及科学适用范围；接口、数据格式和实现约束放在开发文档。
- 发布说明概述版本系列的主要新增功能、兼容性和平台要求。零散的界面和交互修正合并为简短的体验改进说明，不逐项复述开发阶段的小版本记录。
- 使用手册按当前操作组织内容；开发计划、实现细节与逐项修订历史放入开发文档或变更记录。必要的输入条件、数据兼容性和科学解释限制不得因精简而省略。
- 验证报告明确版本、环境、执行命令、范围及未覆盖项。历史通过数量不累计为当前版本的新测试结果。

运行介绍直接说明启动方式和必要条件，避免罗列无关开发工具或与其他软件作不必要比较。操作文字以用户目标、当前状态和处理方法为主；技术细节只在影响操作或结果解释时说明。

## 方法名称与来源

界面选项优先说明计算含义，不用参考软件名称代替功率、归一化或统计定义。论文方法名可保留用于识别；详细来源、参考软件版本及比较差异集中在方法说明、来源记录和致谢中。不得删除第三方版权或许可声明，也不将有限范围的验证写成全面兼容。对照旧结果所需的参数键、端口键和来源字段保持稳定；显示名称变化不改变计算方法或方法版本。

运行说明区分“程序免安装”和“操作系统组件要求”。仅使用发行包的用户无需配置开发工具；不能在打包未提供微软运行库或系统图形库时宣称所有电脑都没有额外要求。

## 版本与内置帮助

根目录 `VERSION` 是版本入口。修改后同步 `PACKAGE_STATUS.json`、当前文档标题和发布命令示例；保留历史报告与引用中的原版本。重新运行 qmake 并构建帮助目录工具，再生成双语参数参考，最后构建应用以更新内置帮助。

程序及目录工具通过同一生成头文件读取编译版本；`VERSION` 是构建依赖。升级旧源码或发现运行版本不一致时，使用新构建目录完成 Release 构建。文档文本一致性检查不等于二进制版本检查，后者必须针对实际分发程序执行，并包含完整的预发布后缀。版本问题处理见[发布维护](../release_maintenance_zh.md)。

在源码根目录运行：

```sh
python tools/help_reference/generate.py --build build-release
python tools/help_reference/generate.py --build build-release --check
python tools/release/test_current_version.py
python -m unittest discover -s tools/help_reference -p "test_*.py"
```

参数参考由任务声明与语言资源生成，不手工维护第二份默认值清单。更新操作说明时核对中英文手册、FAQ、内置帮助链接及发布说明；运行要求变化时同时更新打包脚本生成的 `START_HERE.txt`。详细步骤见[帮助维护](../../tools/help_reference/README.md)。

## 归档与源码导出

当前文档从 `docs/README.md` 进入；版本专属的检查报告放在 `docs/history/`，原始日志和结构化记录保存在 `docs/validation_results/<版本>/`。科学参照数据、测试工具、许可证及依赖来源属于项目材料，不作为临时文件删除。

源码导出排除构建目录、下载缓存、发行程序和 Python 缓存；`package_source.py` 为本次导出重新生成 `PACKAGE_MANIFEST.json`，不能用旧清单说明已修改的源码。清理规则见[发布维护](../release_maintenance_zh.md)。
