# 更新模块设计与维护

软件提供完整程序包下载、官方 HTTPS 来源核验、SHA-256 校验及新目录解压。用户自行关闭旧版、启动新版。模块不覆盖运行中的程序，不删除旧目录，也不迁移数据库与设置。

发布操作和平台验收步骤统一见[发布维护](../release_maintenance_zh.md)；已执行及未执行的检查见[当前验证](../validation_current.md)。

## 版本查询与界面状态

- GitHub 公共 Release API 为首选，按配置回退 Gitee 公共 Release API；镜像查询结果明确标注来源和可能的同步滞后。
- 正式版与 Beta 分开选择，Alpha 仅供开发测试，不参与公开更新。版本比较使用解析后的版本号，不依赖发布时间或标签文本排序。
- 打开窗口查询一次；取消或关闭停止请求。重试时清除旧查询的版本和下载状态，网络错误不能显示为“已是最新版”。
- 更新说明使用受限 Markdown，支持 details/summary 折叠；禁止远程图片、HTML 资源和本地文件加载。用户主动点击的 HTTPS 链接可交由浏览器打开。
- 匹配的更新信息可用时显示来源、目标位置与“下载并解压”；旧发布缺少信息时提供发布页入口。取消读取信息后保持已取消状态。

## 更新信息与来源选择

tools/release/download_metadata.py 根据最终包生成 Aster-update.json，记录版本、平台、文件名、压缩及展开大小、SHA-256 和官方来源。客户端只接受当前平台与所选版本匹配的记录。

自动下载优先使用上次成功来源，首次使用 GitHub；可按既有错误处理切换来源。手动指定来源时不静默切换。始终锁定同一版本、平台、文件及摘要，不拼接不同来源的下载片段，也不按 IP 推断位置。

版本列表查询成功后，GitHub 的信息附件仍可能不可达。客户端对同版本信息的网络错误、超时或缺失按配置回退 Gitee；主动取消、无效信息及不允许的跳转不触发此回退。信息读取与程序包下载是两个独立阶段。

HTTPS 证书正常验证；重定向仅允许代码列明的官方路径。Gitee 的发布附件可经过本仓库 attach_files 路径和 foruda.gitee.com 的受限附件路径。临时 CDN 签名地址不写入持久元数据；下载内容仍需通过大小和 SHA-256 核验。

## 下载、解压与取消

- 流式写入目标位置下的临时文件，校验成功后解压；不提供断点续传。
- libarchive 读取 ZIP/tar.gz。拒绝路径穿越、绝对路径、Windows 设备名、重复或大小写冲突文件、硬链接和特殊设备文件，限制展开体积及条目数量。
- macOS/Linux 保留合法内部符号链接和执行权限，拒绝循环和断链；Windows 包不接受符号链接。
- 解压结果核对 aster-package.json 中的版本、平台及启动入口，再移动到未占用的新目录。目标预先存在或下载过程中被创建时都拒绝覆盖。
- 取消在网络请求与解压分块之间检查；状态通知回调返回后核对操作代次，旧操作不能干扰立即开始的重试。
- 成功后清理临时包；清理失败单独提示，不把已完成的新目录误判为安装失败，不删除用户文件。

## 发布与镜像契约

四个平台从同一提交构建、测试并检查最终包，成功后才准备 GitHub 草稿。桌面发布工作流串行执行；上传前核对包与信息一致性，并逐次检查草稿状态。草稿上传任务结束前不得人工发布，状态查询与附件上传不是原子事务。

Gitee 镜像由 GitHub 程序发行事件触发，只上传四个平台的程序包。通过匿名回读与 SHA-256 核验后，镜像脚本将更新清单写入 Gitee 发行说明里的 `aster-update-v1` 区块。客户端通过官方 API 按标签取正文，并校验清单中的版本、平台、大小、摘要与下载地址。对没有该区块的历史发行版，客户端可读取原有元数据附件。版本查询窗口只显示人工撰写的公告。

GitHub 保存程序发行版、更新 JSON 和校验表。程序公告单独链接到与构建提交对应的依赖材料发行版。镜像的配置、重试和查询方式见[发布维护](../release_maintenance_zh.md#启用-gitee-镜像)。
