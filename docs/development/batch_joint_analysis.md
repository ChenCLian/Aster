# 联合分析：数据身份与执行约定

适用版本：Aster 1.2.0-beta.5。

当前桌面流程通过 `WorkflowDocument` 管理稳定数据身份与节点配对，通过 `RunPlan.batches` 将含联合节点的根任务交给批次执行器。普通根任务沿用原运行器。Welch 交叉谱菜单、节点内配对、双输入预览、按配对保存和绘图导出已经接入；最终原生平台验收仍需完成。

## 职责边界

工作流文档管理节点及输入引用，计划编译器冻结数据身份和依赖关系，批次执行器按依赖就绪状态调度。算法负责数值计算与坐标校验，桌面适配层负责配对、预览、持久化和显示。各层共用稳定数据身份，不按文件名、列表顺序或异步完成顺序重新匹配。

Welch 交叉谱的方法、参数与边界约定见[交叉谱方法约定](cross_spectrum_contract.md)。已记录的独立参考数据和 C++ 数值核对范围见验证入口；计算实现及接口边界见[交叉谱接口说明](cross_spectrum_interfaces.md)。

## 数据和分组身份

- `BatchDataset.id` 标识一份导入数据，由调用方创建并持续保存。改显示名称、重新排序或修改导入选项时保留身份；替换为另一份数据时使用新身份。
- `BatchSeriesRef` 由数据身份、输出端口和可选节点身份组成；`node` 为空时仍指联合节点的树父节点。配对不能只保存文件名、列表索引或先完成的一份数据。
- `BatchPair.id` 标识一组有顺序的 A/B 输入。A/B 交换属于明确的配置变更，不能自动去重为无序集合。
- 同一个参考序列可出现在多个组中。相同的有序配对重复配置会被拒绝；完全相同的序列与自身配对会被拒绝。同一数据的两个不同输出端口可以组成一组。
- 桌面与开发接口均允许显式引用同工作区其他普通节点及其源数据，但排除联合节点及其下游；不存在的节点或成员、错误输出类型、不完整分组，必须在执行前报错。
- 未分配序列不产生联合分析任务，不计为失败；其普通处理分支仍正常运行。

`BatchGrouping` 使用独立 JSON 格式，无显式节点引用时 `schema_version` 为 1；含显式引用时为 2，每个成员增加 `node` 字段，空字符串表示树父节点。读取器严格校验字段、身份和数量，失败时不返回部分有效配置。解码后仍须通过工作流编辑器或计划编译器校验节点、数据和端口的实际语义，包括隐式父节点与显式父节点引用是否等价。原工作流 JSON 保持原格式。

数据分组与横轴对齐是不同步骤。分组框架不对数据插值、不转换单位、不以行号对齐，也不根据相似程度选择配对。坐标兼容性、共同区间与重采样规则由后续分析入口显式检查。

## 任务接口

普通任务继续使用 `TaskInput.data`。双输入任务设置 `TaskDescriptor.pairedInput=true`，通过 `TaskInput.data` 接收 A，通过 `TaskInput.second` 接收 B。两者均遵守该任务声明的 `inputKind`。

`NodeDefinition` 仍只有一个父节点；分组中的 A/B 默认引用该父节点，也可通过显式节点身份选择其他普通节点的兼容端口。运行时不会用默认端口替代缺失的已选端口。

双输入任务必须交给 `BatchWorkflowExecutor`。原 `WorkflowExecutor` 遇到包含双输入任务的子树时，会在计算开始前拒绝执行，避免误用单数据模式。当前科学任务注册表开放 Welch 交叉谱作为双输入算法。

每个分组完成后，其输出以分组身份继续进入普通后续节点。当前版本不支持把已配对的结果再次汇合分组；编辑及计划阶段均拒绝这种结构。

## 计划与调度

`prepareBatch` 接收冻结的工作流、一个源节点、一组带稳定身份的数据和分组配置，生成不可修改的 `BatchSnapshot`。配置中的分组和来源元信息不随界面后续编辑改变。

`prepareLinkedBatch` 接收按源根节点分组的 `BatchSources`。`WorkflowDocument::plan()` 将存在引用关系的根节点组成一个关联批次，彼此独立的根任务仍独立执行。关联批次内数据 UUID 必须全局唯一；不会按名称、顺序或完成先后重新分配引用。

计划中的任务由“节点身份 + 数据或分组身份”定位。任务依赖明确列出生产者和输出端口。多文件执行不依赖文件排序，也不依赖异步完成顺序。

普通任务在一份输入准备好后调度。双输入任务在两份指定输出都完成后调度；工作线程不负责等待另一份输入。并行数为 1 时也能完成配对。某个输入失败时，只阻止依赖它的分组和后续节点。

已有一方输入时，调度器会优先推进另一方尚未完成的上游路径，避免共享参考数据排在列表末尾时先积压大量等待配对的序列。任务完成通知使用预留队列，工作线程通知完成时不再追加分配队列容量。

取消会阻止尚未开始的任务；已运行任务通过现有取消令牌合作结束。调度器不会强制终止正在执行的第三方算法。

`BatchExecutionResult` 按计划顺序返回状态、是否调用算法、诊断及报告。完整输出通过完成回调交付。调用方若需要预览、保存或重试入库，必须显式保留相应只读输出引用。

`BatchSnapshot.manifest()` 记录完整源批次的工作流、数据身份、配对和输入输出定位。传入数据或分组 UUID 时，仅保留该身份的任务及其传递输入依赖，并标记 `scope=item_dependencies`；按任务和数据身份建立索引，不逐个配对遍历全批数据。清单中的源信息是定位与导入选项，不是源文件字节的不可变副本。预览请求键包含选定成员的文件大小和修改时间；点击重算会强制刷新。正式运行重新读取文件。文件在请求冻结后变化或同大小、同时间戳变化仍需用户保留和核对原始文件，未承诺文件系统级快照。

## 资源控制

- 单批（包括关联的多个源根节点合计）最多 10,000 份数据、10,000 个配对、100,000 个展开任务。同批及跨节点计划的未分配候选记录合计均不超过 100,000 条，避免扩展候选列表占用无界内存。
- 并行上限由执行选项指定，合法范围为 1–256；桌面接入时仍应使用应用自身的并行设置。
- 调度器中间输出缓存默认预算为 256 MiB，可通过执行选项配置。只保存实际被后续任务引用的输出端口，同一个只读数据对象按一份数值载荷计算。
- 最后一个使用者完成后，释放调度器持有的生产者输出。
- 超出缓存预算时返回 `BATCH_CACHED_OUTPUT_LIMIT`，并记录当前、追加和允许的载荷字节数；不会无提示地截断数据。

缓存预算不是进程总内存上限，也不是根据电脑性能估算的预算。它不包括调用方保留的源数据、算法工作区、报告结构、工作线程刚产生的结果或观察者保留的数组。大数据最终接入仍需结合算法自身的样本与工作区限制。

## 桌面和存储接入

“管理配对”位于联合节点的步骤设置中。配对表使用绘制委托显示成员，点击或按 Enter 打开单个来源选择器。选择器先列出可用节点，再用虚拟表格显示选中节点的数据与兼容输出，不为每个候选创建控件，也不展开所有节点与数据的笛卡尔积。输入列表保持数据中心的结构；每个配对引用数据 UUID、输出端口及可选来源节点 UUID；来源选择与配对编辑保留显式节点身份；未确认的修改不写入文档。重排与导入选项修改保留 UUID；移除后重新导入会分配新 UUID。节点、连接、布局、参数、源绑定与分组通过 `WorkflowEditor` 原子提交并共用撤销/重做历史。数据库源的创建与绑定为一次编辑；撤销数据删除会恢复原 UUID。历史保留只读数据引用，不复制数值数组，也不保存外部文件字节。运行计划冻结后不再读取界面状态。

预览仅计算选定配对的祖先路径和两个成员。数据、参数或配对变更后递增请求代次，取消旧请求并拒绝迟到回调。上方 A/B 切换只查看实际输入，不重新选择算法输入。

`runJointBatch` 按数据或配对组装记录。普通记录保存其单输入部分；配对记录的 `workflowSnapshot` 保存联合节点开始的执行后缀（根输入边断开），该配对及后续任务所需的完整上游子图、分组及源定位另存于 `provenance.batch_execution`（不包含无关分组和分支），A/B 上游记录 UUID、节点、端口另存于 `input_records`。它是结果记录切片，不可作为单输入工作流重放。重新计算应使用所存的依赖子图、配对信息和原始输入。数据库合并保留 UUID 链接；单独删除上游记录后链接可能无法解析，但配对数值及批次来源清单仍保留。

入库完成后立即释放对应记录输出；待保存的数值载荷另有 512 MiB 固定预算，超限报告错误并合作取消剩余任务。该预算与执行器 256 MiB 中间缓存分别计量，均不代表进程内存总上限；保存失败时保留当前结果供重试，并合作取消剩余任务，避免持续积压失败入库的数值输出；已经在运行的任务仍可能产生额外输出。

交叉谱完整表由算法的 FFT 限额约束。桌面读取完整表并验证报告，再按指标绘制；缺失值和相位包裹跳变以断点表示，不建立大量独立曲线对象。缩放不重复读取该表。PNG/PDF 继承所选指标；CSV 总是导出完整表与单位，并将掩码标记的未定义值留空。

## 跨节点执行基础

`linkedInputOrigins()` 返回类型兼容的普通节点，排除联合节点本身及所有联合节点的后继，因而不会构成联合依赖环。构建计划时先列出普通树路径，再列联合路径；调度仍按真实依赖就绪状态执行，并不是等待所有普通任务结束才运行联合任务。

`batchDependencySlice()` 提取选定节点、配对和实际传递依赖。预览合并 A/B 两条祖先路径，保留定位所需的树祖先定义，但不把未参与的定位祖先作为额外计算输入。来源节点参数修改后请求失效，重新计算实际双输入。实际来源节点、端口和源根节点写入结果来源；跨根进度通知也路由到实际所属根节点。

删除来源节点或数据后，已有引用保持原 UUID 并成为失效引用；新建同名节点或重新导入不会自动接管该引用。撤销可以恢复原绑定。替换或插入操作仍经过完整引用校验，不能删除被引用的端口后静默换用默认输出。

验证见 [alpha.9 跨节点输入记录](../validation_results/1.2.0-alpha.9/linked_input_checks.json)。桌面接入验证见 [alpha.10 记录](../validation_results/1.2.0-alpha.10/linked_input_ui_checks.json)。不支持联合输出再次配对或连接另一个已保存结果批次。若要使用已保存结果，应先导入为普通数据库数据源。
