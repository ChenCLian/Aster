# Aster 工作流契约

## 范围与依赖

核心构建模块包含 model、core 和基础 processing；io、science、application 与 ui 按职责独立。完整分工见 [开发清单](Aster_development_checklist.md)。`model` 与 `core` 不引用 Widgets、图形项、数据库或科学计算外部库。`processing` 的各任务独立存放。

核心可使用 Qt Core 的容器、字符串、JSON 和 UUID；不依赖 GUI 事件循环执行算法。此处不引入网络传输、插件动态加载、DAG 合流、循环、跨树接线或项目存档系统。

## 结构与编辑规则

`WorkflowDefinition` 包含节点列表和单独的布局表。每个 `NodeDefinition` 只有一个可选 `InputBinding`：父节点 ID、父输出的稳定名称、左/右/下槽位。此处是唯一权威连接信息；不存在可被外部独立修改的第二套 children 数组。

源任务必须没有输入连接；普通任务必须有一个输入连接。一个源节点可以生成、读取或接收外部数据。三方向只限制编辑放置，不指定执行优先级。

持久化的逻辑布局为整数格子。每格最多一个节点；子节点必须在父节点声明方向的相邻格。格子被父节点、兄弟分支、其他根或其他节点占用时，都不能放置。左右下最多三个后继，不保证每个节点实际拥有三个可用位置。边界为 ±1,000,000 格，定义最多 10,000 节点。

例如 A=(0,0)、B=(-1,0)、C=(0,1)、D=(-1,1)，连接 A→B、A→C、C→D。D 属于 C，不属于 B。D 放入后，B 向下的空槽不可再用。删除 B 不影响 D；删除 C 同时删除 D。

添加动作必须指定父 ID、槽位、方法，必要时指定上游输出。未指定输出时，优先使用类型兼容的默认输出；否则仅在只有一项兼容输出时自动选择。有多项且默认输出不兼容时要求显式选择。

`previewChild()` 执行相同的结构、参数、端口、位置校验，只返回预检结果，不改变草稿和撤销记录。UI 可据此高亮合法拖放位置。实际 `addChild()` 仍会重新校验，避免预检之后状态变化。

所有编辑先构造候选定义，校验成功后整体提交。失败不改变节点、布局或历史。`setParameters()` 是整组替换，缺少的字段回到声明的默认值，不是增量合并。参数面板应提交完整参数对象。

`removalPreview()` 返回待删除 ID；`removeSubtree()` 按真实父子关系迭代删除整个子树。撤销和重做恢复 ID、参数、关系、布局；新编辑会清空重做。最多保留 100 次成功编辑；历史不包含大型数值数据。树遍历使用迭代方式，避免深树递归栈问题。

不提供任意已有节点拖接、分支合并、中间插入、自动挤开占位格、跨树移动功能。所有拓扑编辑命令均须经过模型校验，图形项不得直接修改父节点。

## 注册与参数

`PROCESS_METHODS(X)` 的每项为稳定方法键与实现类。宏生成方法键常量和注册工厂；方法描述由类的 `descriptor()` 提供。持久化使用键和 `methodVersion`，不使用菜单位置、枚举序号或翻译后的名称。

描述包含分类路径、显示标签、方法版本、输入类型、具名输出、默认输出、参数声明。分类路径天然支持纵向多级菜单。专用参数面板在 UI 层按方法键绑定；注册表不持有 QWidget。

参数目前支持 Number、Integer、Boolean、Text，含默认值、数值范围和文本选项。拒绝未知字段、错误类型、越界值和非法默认值。与输入数据或多个参数联合相关的科学约束由任务执行时验证并返回明确失败信息。

编辑提交时补齐参数默认值；冻结快照也保留注册表的值副本，避免随后注册表变化改变已冻结的定义。工厂必须可重入，不得捕获可变共享算法状态。每次执行都创建独立 `unique_ptr<Task>`。

## 计算数据与输出

`DataRef = shared_ptr<const DataObject>`，DataObject 是四种结构的 variant：

- SeriesData：x、y、轴名称与单位。保证非空、长度一致、数值有限；单调性等要求由具体任务检查。
- SpectrumData：频率、功率及轴信息；长度一致，数值有限且非负。
- GridData：x/y 轴、rows/columns 和一维 values；按 `values[row * columns + column]` 存储，行对应 y、列对应 x。
- TableData：具名数值列和数值行；列名唯一，行宽一致。允许零行表示没有检测到目标。

数据由值构造后只读发布；计算任务需要修改时创建自己的输出。Qt QVector 值复制具有隐式共享，写入新的向量时会分离；不向任务暴露上游的可写指针。禁止 const_cast 或通过旁路修改已经发布的数据。

JSON 用于参数、来源元信息、报告、工作流快照，不用于大型序列或矩阵。二维数组的形状和排列明确包含在类型中；旧 CWT 数据迁移必须核对原数组布局。

`NodeResult` 包含具名输出、状态、报告、警告与错误。成功结果必须满足已声明的输出种类和维度；缺少必需输出、额外未声明输出、非有限数值等都会转为失败。失败／取消节点不能向下游发布输出。

输出可以声明为可选；运行时缺少可选输出不会令生产者失败，但绑定该端口的消费者会因输入缺失失败，其后继阻断。接口不猜测可选输出，也不静默换用其他端口。

每个计算任务只返回结果，不写数据库，不修改 UI，不继承绘图样式。绘图适配由 UI 层处理；io/database 负责存储编码。

## 运行、批量与并发

`freeze()` 只允许合法的非空定义，产生只读 `RunSnapshot`。之后编辑、删除、撤销草稿不影响已有快照。

`prepareRuns(snapshot, selection)` 根据根节点展开请求：需要外部数据的源按所选数据项逐个展开，生成型源每根只生成一个请求。错误的选择归属或缺失选择使准备失败，不发布部分计划。每次 `run()` 创建新的 RunId。

一个 RunRequest 对应一个根节点与一个具体输入。一个森林可以产生多个请求，但每次结果只包含所属根的子树。生成任务也有独立运行 ID。来源标签和 provenance 由应用在提交时提供，不读取界面中的实时状态。

依赖遍历采用父节点先于子节点的广度优先顺序；同层按定义中的创建顺序。物理方向不参与优先级，调整数组顺序也不能使子节点早于父节点执行。每个请求内部顺序运行，多个请求可以由应用安排在线程池中运行。

执行器为无状态对象；快照和输入只读，每个节点独立实例和输出。测试通过 std::async 并发执行 8 个请求，验证运行 ID、输入和参数隔离。BatchRunner 提供 有界 async 调度和事务持久化；持久线程池、公平性、整机资源配额和内部分支并行尚未实现。

`RunResult` 保留当前子树的 JSON 快照、来源信息、起止 UTC 时间、各节点结果及实际调用 execute() 的顺序。数值结果留在内存，随 RunResult/DataRef 的最后一个持有者释放；BatchRunner 按运行落库，保存失败保留结果供重试，成功后不在 batch 列表重复保留大型数值。

## 状态和取消

正常节点事件：Pending→Running→Succeeded。输入或工厂校验失败时可直接 Pending→Failed；不会为未执行的节点伪造 Running。

失败节点的后继成为 Blocked，其他独立分支继续。运行存在成功节点和失败／阻断节点时为 PartialFailed；没有成功节点时为 Failed。这里 PartialFailed 表示存在可保留的成功节点结果，不保证某个最终科学分析分支已经完成。

取消采用共享原子标记和协作检查，不强制终止线程。已成功结果保留，尚未执行的节点变为 Cancelled；正在执行的任务要自行检查 token。任务的长循环定期检查。运行出现取消节点时汇总状态为 Cancelled。

算法或工厂抛出的可捕获 C++ 异常被转换为节点失败。线程不隔离越界访问、abort/exit、系统终止等进程级故障；接入原生库仍须检查参数、返回码、内存和线程安全。事件回调异常进入 observerWarnings，不影响计算结果。事件同步发生在执行器所在的线程；UI 适配器必须通过排队调用或排队信号把它们送回 GUI 线程，不得在回调内直接操作 QWidget。

事件仅包含 RunId、NodeId、状态和文字说明。实际输出从 RunResult 获取，不随每次进度事件复制。

## JSON 与数据库边界

工作流 JSON 的 schema_version=1，包含 nodes 和 layout。节点记录稳定方法键、方法版本、完整参数、输入绑定；布局单独存放。解码器拒绝错误类型和格式版本，返回失败时不提供部分定义。解码后仍须通过 `replaceDefinition()` 做完整语义校验。

这份 JSON 不含数值输入，也不承诺仅凭快照即可复现数据。复现还需保存实际源数据或可恢复的来源，以及对应算法版本。它服务于运行追溯，不代表已经提供用户项目保存系统。

RunId 是运行标识，与数据库自增 ID 分开管理。SaveReceipt 关联 RunId 与数据库记录 ID，并分别报告保存结果。RunState::Succeeded 仍只表示计算成功；持久化成功须检查 SaveReceipt::saved()。

## 桌面适配

WorkflowDocument 持有核心模型及外部源选择，WorkflowCanvas 只处理绘制和命中。目录与参数面板读取注册描述；RunController 在后台调用 BatchRunner 并排队发送事件；ResultsPage 按 ID 读取步骤，PlotView 适配 typed 数据。核心定义、算法和数据库实现未因 UI 改动。

具体文件所有权、传输、布局及后续扩展边界见 [开发清单](Aster_development_checklist.md)。新的编辑行为仍须先成为核心的原子命令，不能只在图形项里改连接。

## 结果显示边界

PlotStyle 与按输出身份组织的会话显示缓存只属于 UI，不进入工作流快照或科学参数。io/exports/csv_export 负责只读数值导出；ExportController 持有 DataRef 并在工作线程写出，关闭窗口时协调取消/等待。修改图形轴标题、对数显示或曲线颜色不会修改持久化数值。详见 [开发清单](Aster_development_checklist.md)。

## 数据传输防护

完整接口接入步骤见 [开发清单](Aster_development_checklist.md)。缺少可选父端口使用 INPUT_PORT_UNAVAILABLE，类型错误附带 expected/actual_type，所有下游诊断补充 parent_id。输出检查包含在执行异常边界中；成功结果不得携带失败诊断。损坏Table回读先核对行字节量和宽度。类型、任务签名和数据库格式不变。


## 数值后端

`math` 的科学公式通过 `math/backend/numeric_backend.h` 调用底层特征求解与 FFT。当前固定使用 LP64 LAPACK/OpenBLAS 与 PocketFFT。数据对象、Task、注册表、执行器、数据库及 UI 不认识原生库类型；线程控制及临时缓冲归适配层管理。详见 [数值后端](numeric_backends.md)。



## 画布显示与 ODP 数据

`ui/workflow/workflow_layout` 从父子关系计算竖向显示坐标，迭代测量子树宽度，保持逻辑网格、端口和执行顺序。控件持有所属父节点 ID，点击/拖放仍走已有模型校验。显示位置不参与数据传递或数据库存储。

ODP 示例由 `io/examples/example_catalog` 校验并按需读取嵌入的原始 TSV，`processing/example_source_task` 用统一任务接口输出 Series。五个方法用同一宏声明/注册；来源字段独立于数值，随 NodeResult.report 保存，`ui/common/source_provenance` 负责显示。示例按所选列跳过缺失对并计数，不隐式重采样。
