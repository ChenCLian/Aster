# 轨道元素、ETP 与日平均日照

本文说明输入、输出、数学约定与适用范围。验证批次、环境和范围见 [验证记录](../validation.md)。

## 界面与使用

在任务页点击「+ 数据源」或空画布的「选择起点」，展开 **数据源 → 天文曲线**。右侧任务目录使用同一注册表，自动出现相同任务：

| 任务 | 输出 | 默认设置 |
|---|---|---|
| La2004 轨道曲线 | 偏心率、地轴倾角、气候岁差，三个独立 Series 端口 | 0–2000 ka，间隔 1 ka |
| La2004 ETP 综合曲线 | 一个 ETP Series | E:T:P 权重 1:1:-1 |
| La2004 日平均日照量 | 一个日照 Series，W/m² | 65°N、太阳黄经 90°、太阳常数 1365 W/m² |

这些都是**无父节点、无需导入文件的数据源**。每个源在一次运行中执行一次，不随其他文件源的文件数量重复。可以添加多个天文源，分别设置参数；批调度器处理它们的并发和数据库写入。

轨道曲线接后续算法时选择需要的输出端口，例如气候岁差 → MTM，或偏心率 → LOWESS → MTM。无需强制增加预处理节点。结果页沿用原有各输出的投图、图形导出、CSV 导出和数据库再次作为数据源功能。
## 年龄、角度、采样约定

- 年龄单位 **ka（1000 年）**；0 是 **J2000**，正值表示距 J2000 向过去。不是相对 1950 年的常规 BP。与其他资料比较时必须核对基准；同一实际时刻的 age(J2000)=age(BP1950)+0.05 ka。
- 用户区间限定为 `0 ≤ start < end ≤ 50000 ka`。官方原文件还包含至 51000 ka 的数据，但本任务不开放 50 Ma 以外的外推。
- 原表间隔 1 ka。输出 X 递增；起点、终点不强制为整数。小于 1 ka 的间隔会显示插值提示，不能视作提高了轨道解本身的时间分辨率。
- 偏心率、地轴倾角作分段线性插值；近日点经度沿相邻样点最短圆弧插值，防止 0/2π 跳变。没有外推。
- 输出年龄是 `start + i × step`，不超过 end；end 不在规则网格上时不追加一个间距不同的末点。报告保存实际末点。
- 采样间隔最小 0.001 ka，输出 2–1000000 点；超限会记录结构化错误，不分配超大数组。
- 内部角度单位弧度；轨道输出倾角为度；偏心率和气候岁差无量纲。
- 默认采用完整精度的官方名义 La2004 过去数据。覆盖范围不代表整个范围内轨道相位具有同等确定性；地质年龄越久，天文解不确定性仍须按原论文理解。
## ETP 与 Acycle 的关系

采用 Acycle `code/guicode/basicseries.m` 的构造原则：选定区间后分别 zscore，再按权重相加：

`ETP = wE*z(e) + wT*z(epsilon) + wP*z(e*sin(pibar))`

z 使用所请求输出网格上的均值与 **N−1 样本标准差**。角度用度或弧度标准化得到相同结果。ETP 默认权重为 1、1、−1；不会对合成后的 ETP 再标准化。零权重项不需要标准化；非零权重项方差为零则报错。全部权重为零允许输出零曲线。

同样的轨道数据，改变所选区间或输出采样间隔会改变标准化参数，这是该定义本身的结果，不是缓存错误。需要跨区间统一标准化的研究应另行定义共同参考区间，不能把不同区间的 zscore 当作相同标度。

对 Acycle 附带 `Example-La2004-1E.5T-1P-0-2000.txt` 的全部 2001 个点，采用 1、0.5、−1 权重核对。容差 1e−4；所列参照比较的最大绝对差约 8.157e−5。参考值不是从 Aster 生成的。这个差异可接受但不是逐位相同；由于未取得 Acycle 生成该示例时的原始 MAT 数据及版本，不把差异原因断言为某一种舍入方式。
## 日平均日照：采用原始近日点角度

实现的是大气层顶、固定轨道参数下，对一天自转平均的辐照度；不是地表到达能量，也不是累积日照时数或全年积分。

令 φ 为纬度，λ 为从当时春分点起算的太阳真黄经，ε 为地轴倾角，ϖ 为 La2004 的**日心**近日点经度：

- `sin(δ) = sin(ε) sin(λ)`；
- `1/r = [1 − e cos(λ − ϖ)] / (1 − e²)`，r 单位 AU；
- 普通昼夜时 `H0 = acos(−tan(φ)tan(δ))`；
- `Q = S0/(πr²) × [H0 sin(φ)sin(δ) + cos(φ)cos(δ)sin(H0)]`。

极昼取 H0=π、极夜取 H0=0。代码以 `sin(φ)sin(δ)` 和 `cos(φ)cos(δ)` 判断，避免极点 tan 溢出；纬度 ±90°、极圈和春秋分均单独纳入验证。

**角度符号是关键**：太阳的地心近日点黄经 = 官方表中的日心 ϖ + π。因此这里距离表达式是减号。它等价于 IMCCE `insolsub.f` 中 `wjour → cwj` 的处理，而不是把日心角度直接当作太阳角度。

太阳黄经 0°/90°/180°/270° 分别表示春分/北半球夏至/秋分/北半球冬至。日照任务同时提供固定月日模式，历法和积分区间约定见 [季节日照](seasonal_insolation.md)。太阳黄经、公历日期及理想历法不是相同的季节定义。默认太阳常数 1365 与 Acycle 界面一致，但可显式更改，并随结果保存。

Acycle `insoML.m` 从岁差量通过 Hilbert 相位估计近日点方向。本版已拥有官方原始 ϖ，无需这个反推近似。`e*sin(ϖ)` 单独不能唯一确定 ϖ，因此不照搬该反推。使用 Berger/IMCCE 的直接天文几何公式，并以独立的昼夜数值积分核验；不承诺与 Acycle 日历采样路径逐点相同。
## 数据与模块

| 位置 | 职责 |
|---|---|
| `resources/astronomy/la2004/` | 官方原始 ASCII、原说明、来源和 SHA-256 清单 |
| `resources/astronomy/astronomy.qrc` | 将轨道数据嵌入程序，运行时无需联网或用户配置路径 |
| `src/io/astronomy/la2004_reader.h/.cpp` | 惰性读取、校验、只读缓存、插值查询 |
| `src/math/astronomy/orbital_elements.h` | 独立轨道元素值类型和角度单位 |
| `src/math/astronomy/astronomical_curves.h/.cpp` | 纯 C++ ETP 与日照计算，不依赖 UI、JSON、Qt 或数值加速库 |
| `src/processing/astronomy_source_tasks.h/.cpp` | 参数描述、数据源任务、标准 Series 输出和诊断 |
| `analysis_tests/astronomy_audit.*` | 数值、边界、数据损坏、并发与完整工作流回归 |
| `analysis_tests/fixtures/` | Acycle 示例及独立日照积分参照；Python 仅用于重建测试参照 |

全进程首次执行天文任务时读取并校验一次，后续共享不可写表，多个数据源不重复解析。官方原始 ASCII 数据约 4.59 MB。

数据库沿用原协议。每个结果保存：原表来源/版本/哈希、年龄基准、插值方式、实际采样区间和点数、ETP 标准化与权重，或日照纬度/太阳黄经/太阳常数。任务参数和版本同时存在工作流快照中。未来变更公式或插值必须增加任务 descriptor.version，不能静默改变旧结果含义。

新增同类函数只需数学函数、Task 包装、注册宏、pro 文件列表、翻译和验证。这里没有增加按任务名硬编码的 UI 或数据库分支。未来新轨道解应单独提供表/来源/范围和读取适配，不把 La2010 只有轨道量的数据冒充含可靠倾角的完整日照解。
