# Aster 1.2.0-alpha.5 性能与完成情况检查

日期：2026-11-07。环境：Linux x86_64 / Qt 6.8.2 / GCC 14.2 / Release / offscreen。完整原始测量与范围见 [performance_checks.json](performance_checks.json)。

## 范围与状态

同批次配对框架、Welch 交叉谱、双输入预览、正式执行、配对记录保存、绘图/导出以及双语帮助已实现。跨批次、跨根节点连接和交叉谱显著性检验不在当前功能范围内。

正式发布验收尚未完成：Windows/macOS 原生构建、真实图形/输入环境、干净系统启动与最终程序包仍需检查。当前版本保留开发版本标识。

## 确认并修复的问题

旧版管理配对窗口为每行同时创建 A/B 下拉控件。1000 组需要 2000 个控件，打开窗口耗时 15.824 秒，进程峰值约 322 MiB；5000 组基线在 45 秒超时后终止，不能将其记作完成时长。

当前窗口只为正在编辑的成员单元格创建选择控件，候选数据模型共享，保持单击选择和键盘确认。滚动编辑最后一行、确认保存和 Escape 取消均有回归检查。

| 测量 | 本机结果 |
| --- | --- |
| 1000 组配对窗口构建 | 21 ms；整次进程峰值 37.4 MiB |
| 9999 组配对窗口构建 | 108 ms；整次进程峰值 69.1 MiB |
| 百万点 / FFT 262144 | 计算 380 ms；结果 131073 个频点 |
| 大频谱首次绘图 / 20 次缩放 | 42 / 86 ms |
| 大频谱 CSV / PNG | 1066 / 230 ms |
| 16 个配对含写库：串行 / 4 线程 | 619 / 243 ms；全部配对载荷哈希相同 |
| 取消响应 | 请求后约 1 ms 返回；本例请求发生于计算开始后 52 ms |

连续十轮切换所有指标后的进程内存峰值趋于稳定；不能据此证明不存在任何泄漏。性能测试使用合成数据、固定配置和本机时钟，不构成用户硬件上的速度保证。正常界面的 CSV 导出在线程中执行，表中为直接同步 API 的测量。

## 验证与兼容性

本次受影响的五个 Qt 测试目标共 966 通过、0 失败、0 跳过；计数含初始化与清理。发布工具 97 项、帮助生成器 6 项通过。中英文参数参考与 54 个任务、233 个参数声明一致。

两项重新运行恢复测试的等待条件补充了有效记录 ID 检查，避免将异步加载期间的 0 误判为新记录；结果加载的生产代码未修改。初次检查与复验说明保留在 JSON 记录中。

生产代码仅修改配对面板。算法、参数限额、数据库结构和本机依赖配置未改变，alpha.4 的数值证据单独保留，没有把其历史 1883 项计为本次完整回归。可重复测量方法见[性能工具说明](../../../tools/performance/README.md)。
