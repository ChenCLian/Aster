## 缺陷与修复

1. **来源索引的释放后读取。** ASan 在 10000 节点的编辑测试中捕获哈希表扩容后的失效引用。对同一哈希表读写时先复制父节点来源，再插入子节点；编辑校验、跨节点计划和文档预览三个同类位置均修复。新增两支路共 1024 个节点的测试，核对来源身份、实际计算、预览与撤销/重做。
2. **大规模配对窗口重复复制列表。** 从共享容器临时值读取成员时，非 const 下标引发整份数据或名称列表复制。改为只读访问，避免逐行复制。9999 对的窗口构造中位耗时由 13574 ms 降至 1009 ms；使用相同计时程序、环境及三次独立进程比较。
3. **同批未分配候选缺少合计保护。** 原限制分别作用于每个联合节点。现在按整个冻结批次累计，保持 100000 条候选的边界，与跨节点路径一致。回归验证 99900 条可接受、101898 条被拒绝，修复前同一拒绝断言可重现失败。

4. **批量运行时界面更新过密。** 512 对实际运行的首次三次测量中，最长事件循环间隔为 201–1745 ms。逐事件诊断和单独断开进度/保存通知的对照定位到目录刷新与进度重绘交错。进度、文件状态和目录查询改为 100 ms 合并显示，全部步骤仍计数，结束时立即更新。两个 1000 事件突发用例验证进度仅更新一次、正常结束与中途错误前已保存结果可见、取消提示不被延迟进度覆盖、结束后没有迟到刷新，以及新运行能恢复进度。修复前数据保留于 `gui_before_refresh_fix.json`。

第三项只收紧候选元数据保护的执行范围，不修改科学计算、模拟次数、样本预算、工作量预算或数据格式。保留的历史验证文件不重写。

性能工具同时修正了非阻塞窗口的计时口径，增加失败退出校验、并行输出对比、跨节点调度和主窗口事件循环测量。

计数包含 QtTest 初始化、清理和参数化数据行。专项复测、内存诊断及历史通过数不与该总数累加。

终轮完整执行曾在 `cancelledCloseClearsRestartRequest` 出现 1 次 5 秒时限超时（当次 1992 通过、1 失败）。未修改源码，随后单项连续 3 次通过，整个更新测试程序 50 项复测通过；上表使用该程序的复测结果。首次失败与复测记录见 [regression_attempts.json](../validation_results/1.2.0-alpha.10/release_audit/regression_attempts.json)。这是未稳定复现的计时敏感项，尚不能证明其环境原因，原生验收须关注语言切换与关闭确认。

- 随机跨节点测试采用 12 个固定种子，每个种子 24 个配对，分别使用 1/4/8 个工作线程。逐点核对 512 点独立解析表达式，涵盖同名数据、数据重排、不同支路与源根以及配对后继预览。
- 重新生成 16 组模拟数据、8 组真实 ODP 数据的独立交叉谱参照；与已有参照一致，直接 DFT 核对通过。NumPy 2.3.5、SciPy 1.17.0。此项不构成新的显著性或统计误报率校准。
- 独立 ASan/UBSan 构建对 core、batch、cross-spectrum、joint-UI、rewrite、linked-input 六个程序运行 **331 项**，未报告地址错误或未定义行为。预编译 Qt/数值依赖未插桩，未执行 ThreadSanitizer。
- **泄漏扫描未完成。** 当前运行环境使 LeakSanitizer 在退出扫描时报 ptrace 环境错误；随后明确禁用泄漏扫描再运行 ASan/UBSan。不能据此宣称没有内存泄漏。
- 发布脚本 Python 测试执行 95 项，无失败；另 2 个 Homebrew 查询用例因缺少 Ruby 未执行（整类跳过）；帮助生成测试 6 项通过；54 个任务、233 个参数的双语参考保持同步。文档资源重新构建后，8 个帮助测试函数及初始化/清理共 10 项通过；Linux/macOS 打包脚本语法检查通过。

## 性能与响应

硬件：INTEL(R) XEON(R) PLATINUM 8573C，可见 9 个逻辑处理器，约 9.7 GiB 内存。每次测量使用新进程，在编译和回归结束后串行执行。除另有说明外，数值为中位数（最小–最大），单位 ms。

| 场景 | 测量 |
| --- | ---: |
| 1000 对：配对窗口构造，3 次 | 315（264–1588） |
| 9999 对：配对窗口构造，3 次 | 1009（354–1112） |
| 修复前 9999 对：相同计时程序，3 次 | 13574（13566–22488） |
| 两份百万点序列：Welch 计算，3 次 | 263（254–342） |
| 百万点序列：请求取消后的返回延迟，5 次 | 2（1–14） |
| 主窗口 512 对：后台运行并保存 1025 条结果，3 次 | 1226（939–1310） |
| 同场景：10 ms 心跳观测到的最长事件循环间隔，3 次 | 25（25–41） |

计时有明显波动。9999 对首轮成员选择器最长 4614 ms、确认成员最长 7327 ms，均保留在原始记录中。同一二进制另做 3 次专项复测：窗口构造 415–515 ms、成员选择器 21–264 ms、确认成员 77–310 ms。复测额外记录了进程 CPU 时间，未替换上表首轮数据；这些波动不作为固定响应时限保证，原生验收需继续检查大规模配对操作。

9999 对跨节点调度的单次压力测量：计划构造 326 ms，1/4/8 工作线程执行分别为 8162 / 4387 / 3464 ms，各配对输出编码逐字节一致。此场景复用不可变的 512 点输入缓冲区，用于验证任务规模与共享参考；不表示同时载入 9999 份大型文件的内存开销。

主窗口计时截至运行控制器转为空闲，未计入随后所有结果加载完成的时间。主窗口 512 对使用独立分配的 4096 点输入，进程峰值 RSS 最大 124.7 MiB。百万点、大 FFT（262144）绘图压力测试包含指标切换、20 次缩放、CSV/PNG 导出及 10 轮指标循环；指标切换最长 413 ms，进程峰值 RSS 最大 115.3 MiB。9999 对配置下仅预览选定配对，准备后的异步就绪最长 355 ms。

原始测量见 [performance_runs.json](../validation_results/1.2.0-alpha.10/release_audit/performance_runs.json)，复现入口见 [性能工具](../../tools/performance/README.md)。峰值 RSS 不是实时分配量或泄漏证明；offscreen 不包含系统合成器、远程桌面和多显示器的延迟。取消为合作式取消，原生库调用内部的等待不保证与此案例相同。
