# Aster 1.3.0-beta.11 定向检查与修复

本轮按要求只检查近期新功能及关联操作链，重点是“应用到当前流程的全部数据／配对”，并补查新帮助目录与检索。未把此前全软件或完整数值测试计为本轮通过项。

## 已复现并修复

1. **继承的逐点决定丢失**：恢复的节点可能把逐点保留／排除决定放在基础参数里，而不是单独覆盖表。旧批量逻辑只保留覆盖项，导致批量修改普通参数时丢失这些决定。现在按每个现有输入的有效值保留；显式清空仍为空，新加入的数据也不继承旧决定。
2. **批量来源缺少归属校验**：底层接口原本只对单条修改校验来源；批量调用会接受已删除或其他流程的数据 ID。现在两种操作均校验当前归属，拒绝失效来源，且不改变工作流和撤销历史。这是接口防护缺口，不宣称已经观察到正常界面必然误广播。

实际应用代码只修改 src/ui/workflow/workflow_document.cpp。回归分别补在 ui_tests/ui_tests.cpp 与 joint_ui_tests/joint_ui_tests.cpp，相关中英文用户说明和自动参数维护约定同步更新。数值算法、任务默认值、数据库格式、打包脚本及 Actions 未改。

## 额外覆盖的容易遗漏情形

- 同名文件重排后，设置仍跟随数据 ID；不按文件名或列表位置混用。
- 未打开参数面板的数据照常获得确定规则；自动规则与手动固定值可以在同一节点并存。
- 批量设置只作用于当前节点；兄弟分支和其他流程保持原设置。
- 后加入的数据与配对继承基础规则；已删除来源不能再次作为批量起点。
- 自动规则按实际输入解析，不把窗口点数等运行结果写回；冻结的运行请求不受后续编辑影响。
- 图结构及配对序列化后恢复，实际运行并保存；撤销重做恢复原来的个别参数。
- 输入参数后未等待延时提交就切换数据，再批量、撤销、重做，验证当前显示与实际作用对象一致。
- 一条短数据无法满足自动窗口要求时明确失败，其他有效输入正常完成并保存。
- 5000 条输入的批量设置只改参数信息，继续共享原始数值数组；仅作为该操作的小规模性能检查。

详细数量、失败复现、最终通过日志和未覆盖平台见 [本版验证范围](../../../validation_current.md)。本版仍需在 Windows/macOS 原生环境检查系统缩放及发行包行为。
