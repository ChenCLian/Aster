# 从已有构建补建发布草稿

适用于四平台已完成构建、测试和打包，但启动时没有勾选 `prepare_draft` 的情况。不需要重新编译，也不需要把大型附件下载到个人电脑后再上传。

1. 将 `.github/workflows/prepare-release-draft.yml` 及其选择脚本和测试提交到默认分支。
2. 打开 GitHub Actions → **Prepare draft from existing build** → **Run workflow**。
3. 在 `build_number` 填写 **Build desktop packages** 的运行编号，例如页面显示 `#38` 时填写 `38`。这不是地址栏中的长数字 Run ID，也不加 `#`。
4. 等待工作流完成，然后在 Releases 检查生成的草稿。确认附件与说明后再手动发布。

选择器要求同一官方构建运行成功完成，且四个 `program-*` 和四个 `dependency-materials-*` 附件全部存在、未过期。不接受只执行测试的运行、单平台运行、失败运行或缺少附件的运行。

程序包直接复用所选运行的附件；源码和公告取自该构建对应的提交，发布标签也指向该提交。新增补建工作流的提交不会被误当作程序源码版本。下载程序包后仍检查包内平台/版本标记并生成 SHA-256 和更新元数据。

只准备或更新草稿，不自动发布，不自动同步 Gitee；已公开的同名 Release 不会被覆盖。依赖材料仍只放在 GitHub，Gitee 的同步规则不变。既有草稿的手动标题和公告由原发布工具保留。

该流程仍需 GitHub 下载并上传附件，耗时取决于材料大小，但不重新执行 qmake、C++ 编译或依赖源码收集。附件已过期或被删除时，应重新构建，不能用不完整附件发布。

首次加入时，只需提交新的工作流、脚本、测试和本文档；无需修改程序版本号或重新创建旧构建。
